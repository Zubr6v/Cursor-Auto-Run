# Cursor Auto Run

Windows-програма, яка може підтвердити команду в Cursor замість вас. Вона дивиться лише на вікна процесу `Cursor.exe` через Microsoft UI Automation і викликає `InvokePattern.Invoke` на кнопці підтвердження, якщо текст команди проходить локальні правила.

Програма типово вимкнена. Після запуску нічого не натискається, доки ви не увімкнете Auto Run.

## Що це не робить

Cursor не публікує зовнішнього API для схвалення команд. Кнопки Run / Allow живуть в інтерфейсі редактора, тож програма працює як клієнт UI Automation, так само як програма читання з екрана.

Вона навмисно не обходить захист Cursor і Windows:

- не надсилає клавіші й не клікає мишею;
- не підключається до налагоджувача і не відкриває Chrome DevTools;
- не викликає внутрішні команди редактора;
- не змінює налаштування Run Mode, пісочницю чи UAC;
- не чіпає інші процеси, зокрема вікно підвищення прав;
- не натискає Reject, Cancel, Deny, Skip, Allow list і Run and Debug;
- не підтверджує запуск поза пісочницею.

Якщо напис кнопки чи текст команди прочитати не вдалося, натискання не буде. Власне правило не може дозволити команду з жорсткого списку нижче.

Вбудовані режими Cursor лишаються окремо: **Settings → Agents → Approvals & Execution**. Їх описано в [Run Modes](https://cursor.com/docs/agent/security/run-modes). Ця програма їх не вимикає і не замінює.

## Режими

| Режим | Що може натиснути |
| --- | --- |
| Безпечний | Читання файлів, перегляд git, тести, локальна збірка і видимий скрипт без заборонених дій: `pytest`, `npm test`, `npm run build`, `cargo test`, `dotnet test`, `git status`, `Get-Content` |
| Звичайний | Те саме, плюс залежності і звичайні команди розробки: `npm install`, `pip install`, `git commit`, `git pull`, `docker build` |
| Ручний | Нічого. Сканування лише показує, що видно у вікні |

Завжди лишається ручним підтвердженням:

- видалення файлів (`rm`, `del`, `Remove-Item`, `git clean`, `git reset`, `npm ci`, `make clean`);
- форматування і операції з диском (`format`, `diskpart`, `mkfs`);
- `sudo`, `runas`, `Start-Process -Verb RunAs` і зміна системи (реєстр, служби, брандмауер, вимкнення);
- публікація і розгортання (`git push`, `npm publish`, `docker push`, `kubectl`, `terraform apply`);
- однорядкові невідомі скрипти, `python -c`, закодований PowerShell, `curl | bash`;
- секрети й облікові дані (`.env`, ключі, `token=...`);
- запуск поза пісочницею.

## Інтерфейс

- перемикач Auto Run;
- статус: зупинено, працює або пауза;
- лічильник автонатискань;
- історія рішень;
- затримка перед натисканням (0–5000 мс);
- запуск разом із Windows (запис поточного користувача `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, без підвищення прав);
- Пауза і Стоп;
- додаткові назви кнопок для інших версій Cursor;
- власні дозволені команди;
- перевірка команди без натискання;
- гаряча клавіша, типово `Ctrl+Alt+A`;
- іконка в системному треї. Закриття вікна ховає програму, вихід — з меню трея.

Кнопка **Сканувати вікна Cursor** один раз читає дерево доступності і нічого не натискає.

### Власні команди

Один запис на рядок:

```text
tools\check.bat
safe:python scripts\check.py
safe:re:^python scripts\\check\.py\b
```

Префікс діє у звичайному режимі. Префікс `safe:` додає команду і в безпечний режим. `re:` — регулярний вираз. Занадто широкі вирази на кшталт `.*` ігноруються. Жодне власне правило не пропускає команду з жорсткого списку.

Додаткові назви кнопок теж не можуть бути Reject, Cancel, Deny, Skip або Allow list.

## Вимоги

- Windows 10 або 11
- Python 3.12 або новіший, якщо запускати з джерела
- Відкритий Cursor. Процес має називатися `Cursor.exe`

Підтвердження шукається за доступним іменем кнопки: `Run`, `Allow`, `Run command`, `Continue`, `Allow once`, `Run in sandbox`. У Cursor 3.28 і новіших кнопки чату мають мітки для зчитувача екрана. Якщо сканування бачить вікно, але не бачить кнопку, оновіть Cursor. Програма не вмикає прихований режим доступності самостійно і не вгадує координати кнопки.

## Запуск

Відкрийте файл **`Запустити.bat`** подвійним кліком. Команди вводити не потрібно.

За першого запуску файл сам створить середовище і встановить компоненти, після цього відкриється вікно програми. Наступні запуски відкривають вікно одразу. Якщо зібрано EXE, цей самий файл запускає `dist\CursorAutoRun\CursorAutoRun.exe`.

Потрібен Python 3.12 або новіший з позначкою Add python.exe to PATH. Його ставлять один раз з [python.org](https://www.python.org/downloads/).

Автозапуск і гаряча клавіша працюють після встановлення залежностей для Windows: `uiautomation` і `comtypes`. На інших системах відкривається той самий інтерфейс і перевірка правил, але кнопки Cursor не натискаються.

Налаштування зберігаються в `%APPDATA%\CursorAutoRun\settings.json`, історія — в `history.jsonl` поруч. Історія містить текст дозволених і відхилених команд, значення на кшталт `token=...` замінюються на `<приховано>`.

## Збірка EXE

На Windows:

```bat
build.bat
```

Готовий файл: `dist\CursorAutoRun\CursorAutoRun.exe`. Збірка використовує PyInstaller і не є одним файлом: поруч з EXE лежать бібліотеки PySide6, так програма стабільніше знаходить плагіни Qt.

## Перевірки

Логіка правил, обхід дерева кнопок, затримка і вікно покриті тестами. Їх можна запустити без Windows:

```bat
pip install -r requirements-dev.txt
pytest
```

Реальний виклик `Invoke` у вікні Cursor потрібно перевірити вже на Windows: увімкнути безпечний режим, натиснути **Сканувати вікна Cursor** і переконатися, що в історії є команда, перш ніж залишати Auto Run увімкненим.

## Як влаштоване рішення

1. Потік монітора ініціалізує UI Automation у своєму потоці.
2. Серед вікон робочого столу лишаються лише ті, чий процес має ім’я `Cursor.exe`.
3. Обхід шукає кнопку картки підтвердження. Підпис може бути `Run` або `Run step`. Поруч мають бути Skip, Reject або Always Run, тому пункт меню Run не чіпається. Skip, Always Run і Allowlist теж не натискаються.
4. Текст команди береться з найближчого невеликого контейнера кнопки, а не з усього вікна чату. Видимий скрипт PowerShell у цій картці читається цілком.
5. Політика повертає дозвіл, заборону або «невідомо». Однорядкова невідома команда не натискається. Багаторядковий скрипт без заборони зі списку вище — натискається.
6. Після затримки кнопка має все ще бути на місці, а рішення — тим самим. Спершу викликається `Invoke`, потім стандартна дія цього елемента, і лише тоді клацання по ньому. Клавіші у вікно не надсилаються.
7. Подія пишеться в історію. Повторне натискання тієї самої кнопки блокується кілька секунд.
